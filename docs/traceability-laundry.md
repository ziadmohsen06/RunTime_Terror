# Traceability: Laundry Tracking (FR1, NFR1)

Maps each user story to the tests that cover it. All paths are relative to `backend/`.

**Source of the stories.** US-L1 is the core story from `docs/Milestone1_Idea_and_Architecture.pdf`. The others are **derived** from the laundry rules and the Laundry page. **Please check them against your team's story list.**

- **SVC** = `tests/unit/laundry/LaundryService.test.ts`
- **STATE** = `tests/unit/laundry/ItemStatusMachine.test.ts` (all 36 status pairs)
- **BEHAVIOUR** = `tests/unit/laundry/ItemStateBehaviour.test.ts` (what each state does: next status and entry side effects)
- **STAGE** = `tests/unit/laundry/LoadStageMachine.test.ts` (all 16 stage pairs)
- **GROUPS** = `tests/unit/laundry/groups.test.ts`
- **REPO** = `tests/unit/contracts/loadRepositories.contract.test.ts` (in-memory and SQLite)
- **E2E** = `tests/e2e/laundry.e2e.test.ts`
- **ERR** = `tests/e2e/laundry.errors.e2e.test.ts`
- **PAGE** = `tests/unit/frontend/laundryPage.test.ts`
- **PAGES** = `tests/unit/frontend/pages.test.ts` (checks every page, including `laundry.html`)

| ID | User story | Tests |
| --- | --- | --- |
| US-L1 | As a user, I want to group my dirty clothes into loads by color and fabric and track each load until it is clean, so that I know what is ready to wear and avoid damaging clothes by mixing them. | SVC `creates a PENDING load and puts the items in laundry`, `PENDING -> WASHING puts the items in WASHING`, `WASHING -> DRYING puts the items in DRYING`; BEHAVIOUR `IN_LAUNDRY goes to WASHING`, `WASHING goes to DRYING`; STAGE `allows %s -> %s`; E2E `happy path: dirty items -> load -> washing -> drying -> done, items return to the closet`, `lists loads with their stage`; PAGE `lists the four stages in order` |
| US-L2 | As a user, I want to mark an item dirty so that it can be washed. | SVC `moves a clean item to dirty through updateStatus`, `returns only the user's dirty items`; E2E `happy path: dirty items -> load -> washing -> drying -> done, items return to the closet` |
| US-L3 | As a user, I want the system to stop me adding an item to a second active load so that my laundry status never becomes inconsistent. | SVC `an item cannot be in two active loads`, `a finished load frees its items for a new load`; REPO `finds the ACTIVE load that contains an item`, `ignores DONE loads when looking for an active load`; E2E `rejects putting an item in a second load with a 409`; PAGE `409 on create keeps the server sentence (item already in a load)` |
| US-L4 | As a user, I want an invalid status change to be refused with a clear message and no data changed so that my clothes keep a correct status. | STATE `rejects %s -> %s`, `puts both statuses in the error message`, `error carries HTTP status 409`; SVC `rejects an item that is already dirty and changes nothing`, `rejects an item that is not dirty and changes nothing`, `a DONE load cannot advance and changes nothing`, `restores item statuses and the stage if one update fails`; E2E `rejects an invalid status change with a 409`; PAGE `409 on advance says the load cannot move on`, `409 on mark dirty says the item is already dirty or in the laundry` |
| US-L5 | As a user, I want to take an item out of a load before washing starts so that it goes back to my dirty items. | SVC `puts the item back to DIRTY and keeps the rest of the load`, `deletes the load when its last item is removed`, `the removed item can join a new load`, `is rejected once washing has started, and changes nothing`, `rejects a finished load, so a clean item is never made dirty`; E2E `removes an item from a pending load and it becomes dirty again`, `refuses to remove an item once washing has started`; PAGE `items can be removed only while the load is pending`, `409 on remove says items can only be removed before washing starts` |
| US-L6 | As a user, I want a load to hold only items of the same color group and fabric group so that colors do not run and delicate clothes are not damaged. | SVC `rejects mixed color groups and changes nothing`, `rejects mixed fabric groups`; GROUPS `colorGroupOf`, `fabricGroupOf`; E2E `rejects mixed colors with a 400 and changes nothing`; PAGE `400 on create keeps the server sentence about mixed groups` |
| US-L7 | As a user, I want clothes that need ironing to go to the ironing queue when a load finishes, and the rest to become clean, so that I know what to iron. | SVC `DRYING -> DONE sends items that need ironing to IRONING and the queue`, `restores the statuses and the stage if joining the ironing queue fails`; BEHAVIOUR `DRYING goes to IRONING when the fabric needs ironing`, `DRYING goes straight to CLEAN when the fabric does not need ironing`, `entering IRONING adds the item to the ironing queue`, `a failing queue makes enter() fail, so the caller can undo`; E2E `happy path: dirty items -> load -> washing -> drying -> done, items return to the closet` |
| US-L8 | As a user, I want a Laundry page that looks and works like the other pages (sidebar, light and dark theme, ironing link) so that the app feels consistent. | PAGE `loads the shared theme, auth client and shell, in that order, in the head`, `has the main area the shell wraps with the sidebar`, `has a section for clean items, dirty items and loads`, `laundry.html has no hardcoded hex color`; PAGES `laundry.html loads the auth client in its head`, `laundry.html calls the API through authFetch, never plain fetch`, `laundry.html links to the ironing page` |
| US-L9 | As a user, I want clear messages for errors, and to be sent to the login page when my session has expired, so that I know what went wrong. | ERR `post /laundry/loads without a token is rejected` (and the other five routes), `a tampered token is rejected`; E2E `returns 400 for a bad request body or id`, `returns 404 for an unknown load or item`; PAGE `401 says the session expired`, `404 says it no longer exists and the list was refreshed`, `400 without a server sentence asks to check the selection`, `a server error mentions the status code`, `no status at all means the server could not be reached` |
| US-L10 | As a user, I want to see and change only my own laundry so that nobody else can touch it. | SVC `rejects another user's item`, `returns only the user's dirty items`; REPO `lists only the user's own loads`; ERR `they see none of my loads or dirty items`, `they cannot advance my load`, `they cannot remove an item from my load`, `they cannot mark my item dirty or put it in their own load` |
| US-L11 | As a user, I want my loads to still be there after the server restarts so that I do not lose track of my laundry. | REPO `keeps loads when a new repository opens the same database`; E2E `keeps loads after the app is rebuilt on the same database` |
